# 认证缓存

## 解决的问题

原来的 JWT 过滤器每次都按用户名查询 `sys_user`：

```text
JWT -> 查询 MySQL -> 建立认证信息
```

用户认证信息在短时间内不会频繁变化，因此适合缓存。

## 两层缓存

```text
Caffeine 本地缓存
  -> Redis
  -> MySQL
```

- Caffeine：速度快，但只在当前 JVM 内有效。
- Redis：多个后端实例可以共享，但有网络开销。
- MySQL：权威数据源。

## 缓存内容

```text
userId
username
role
enabled
```

不要把密码哈希放入缓存。

## JWT

JWT 只保存用户 ID 和标准时间字段，不再保存用户名和角色。

过滤器通过 `uid` 查找认证缓存。

## 失效

用户被禁用、角色变化或认证数据变化时，需要同时清除：

- Caffeine 本地缓存
- Redis 缓存
