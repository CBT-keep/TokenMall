# TokenMall 14 天学习与开发路线

## 1. 总体安排

| 项目 | 安排 |
| --- | --- |
| 周期 | 14 天 |
| 每日投入 | 8 小时及以上 |
| 学习方式 | 先跑通简单版本，复现问题，再亲自实现优化 |
| 支持方式 | AI 提供需求、骨架、CRUD、前端、实验、代码审查和知识库 |
| 每日产出 | 代码、SQL 或实验结果、提交记录、Obsidian 教程和复盘 |

建议每天按以下节奏安排：

| 时间段 | 时长 | 内容 |
| --- | --- | --- |
| 上午一 | 2 小时 | 阅读原理、教程和目标代码 |
| 上午二 | 2 小时 | 实现当天核心功能 |
| 下午一 | 2 小时 | 完成实验、复现问题和对比结果 |
| 下午二 | 1 至 2 小时 | 修复、补测试、整理证据 |
| 晚上 | 1 小时 | 复盘、提交代码、更新知识库 |

## 3. 每日完成标准

每一天结束时必须满足：

1. 当天代码可以编译和运行。
2. 当天新增接口可以用 HTTP 文件、curl 或前端操作。
3. 至少有一条可重复验证的证据，例如 SQL 结果、日志、测试输出或监控截图说明。
4. 至少有一个失败场景被主动复现，而不是只实现正常流程。
5. 当天的问题编号在 Obsidian 中有关联链接。
6. 提交信息包含天数和主题。
7. 知识库索引成功更新。

推荐提交格式：

```text
day01: verify local environment and baseline flow
day05: reproduce and fix inventory oversell with mysql
day14: finish redis mq seckill flow and reconciliation
```

## 4. 学习问题台账

### 4.1 MySQL 问题

| 编号 | 问题 | 触发方式 | 学习目标 |
| --- | --- | --- | --- |
| MYSQL-01 | 表结构缺乏关键约束 | 检查索引和唯一键 | 理解数据模型 |
| MYSQL-02 | CRUD 与业务 SQL 边界不清 | 追踪请求和 SQL 日志 | 理解 MyBatis-Plus |
| MYSQL-03 | 并发扣减发生超卖 | 并发调用下单接口 | 理解事务隔离 |
| MYSQL-04 | 重复支付产生重复 Token | 重复调用支付接口 | 理解幂等和唯一索引 |
| MYSQL-05 | 超时关闭与支付并发冲突 | 同时支付和关闭订单 | 理解状态机 |
| MYSQL-06 | 慢查询与索引失效 | 使用 EXPLAIN 分析 | 理解索引 |

### 4.2 RabbitMQ 问题

| 编号 | 问题 | 触发方式 | 学习目标 |
| --- | --- | --- | --- |
| MQ-01 | 消息发送成功但业务事务回滚 | 模拟事务异常 | 理解一致性问题 |
| MQ-02 | 消费者异常导致消息丢失 | 消费时抛异常 | 理解 ACK |
| MQ-03 | 消息无限重试 | 持续抛出异常 | 理解重试和 DLQ |
| MQ-04 | 重复投递导致重复发 Token | 重复发送同一条消息 | 理解消费幂等 |
| MQ-05 | 消费者积压 | 降低消费能力并批量发送 | 理解削峰和并发 |
| MQ-06 | 超时任务只能轮询 | 关闭订单任务 | 理解延迟消息 |

### 4.3 Redis 问题

| 编号 | 问题 | 触发方式 | 学习目标 |
| --- | --- | --- | --- |
| REDIS-01 | 商品每次都查询数据库 | 压测商品详情 | 理解 Cache Aside |
| REDIS-02 | 更新数据库后缓存仍是旧值 | 更新后立即查询 | 理解缓存一致性 |
| REDIS-03 | 不存在的商品持续查询数据库 | 请求随机不存在 ID | 理解缓存穿透 |
| REDIS-04 | 热点 Key 过期导致数据库峰值 | 热点商品同时过期 | 理解缓存击穿 |
| REDIS-05 | 大量 Key 同时失效 | 批量设置相同 TTL | 理解缓存雪崩 |
| REDIS-06 | 锁过期后释放了别人的锁 | 延长业务执行时间 | 理解锁所有权 |
| REDIS-07 | Redis 扣成功但订单创建失败 | 模拟消费者失败 | 理解最终一致性 |
| REDIS-08 | 秒杀请求直接压垮 MySQL | 高并发抢购 | 理解预扣和削峰 |

## 5. Redis、MQ 和 MySQL 的职责边界

| 问题 | MySQL | Redis | RabbitMQ |
| --- | --- | --- | --- |
| 最终数据 | 权威数据源 | 不承担永久存储 | 不承担最终存储 |
| 商品缓存 | 保存商品 | 保存热点副本 | 发送缓存失效事件 |
| 库存扣减 | 最终库存事实 | 秒杀预扣和原子判断 | 异步下单和补偿 |
| 订单创建 | 保存订单 | 可缓存可售状态 | 削峰、重试和延迟 |
| Token 发放 | 保存余额和流水 | 缓存余额或幂等标记 | 支付后异步发放 |
| 超时关闭 | 更新订单状态 | 可辅助延迟任务 | 延迟队列主实现 |

## 6. AI 与学习者的分工

### AI 负责

- 项目需求、架构、数据模型和接口契约。
- 可运行的项目骨架和基础 CRUD。
- 前端全部页面和接口调用。
- JWT 安全框架和基础配置。
- 简单 MySQL 版本，保留明确问题。
- 每日教程、实验说明和复现脚本。
- 代码审查、报错分析和知识库更新。

### 学习者负责

- 理解需求后亲自编写 Redis、RabbitMQ 和关键 MySQL 代码。
- 运行并发、故障和重复投递实验。
- 记录实际结果并判断是否满足验收标准。
- 亲自解释每个方案解决了什么问题以及引入了什么新问题。

## 8. 结束标准

第 14 天结束时，需要能够独立画图并解释以下链路：

1. 浏览器请求到 Spring Boot 再到 MySQL 的完整路径。
2. 商品缓存从创建、命中、失效到重建的路径。
3. 支付成功后通过 RabbitMQ 发放 Token 的路径。
4. 失败消息进入死信队列并人工重放的路径。
5. 超时订单关闭并释放库存的路径。
6. 秒杀请求从 Redis 预扣、MQ 下单到 MySQL 持久化的路径。
7. Redis、RabbitMQ 和 MySQL 状态不一致时的发现与补偿路径。
