# TokenMall 用户需求与产品需求

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | TokenMall 学习商城 |
| 项目代号 | token-mall |
| 目标用户 | 项目学习者、普通购买用户、商城管理员 |
| 核心目标 | 通过一个可运行的 Token 电商项目系统学习 Redis、RabbitMQ 和 MySQL |

## 2. 产品定位

TokenMall 不是生产级商城。它是一个故意保留问题、能够复现并发和可靠性故障的学习实验室。

产品提供两类数字商品：

1. Token 资源包
   - 一次性购买。
   - 支付成功后直接增加资源包 Token 余额。
   - 可以加入购物车。
   - 库存可以是有限库存，也可以配置为充足库存。

2. Token Plan
   - 具有有效期和总 Token 配额。
   - 普通销售时可以加入购物车。
   - 秒杀活动中的 Plan 使用单独下单入口，不经过购物车。
   - 支付成功后生成用户 Plan 记录。
   - 秒杀场景是项目的核心综合实验。

## 5. 核心业务流程

### 5.1 普通商品购买

1. 用户浏览商品。
2. 用户选择 SKU 并加入购物车。
3. 用户提交所选购物车项。
4. 系统创建待支付订单。
5. 系统执行库存占用或扣减。
6. 用户调用模拟支付接口。
7. 支付成功后订单变为已支付。
8. 系统发放资源包 Token 或生成 Token Plan。
9. 用户查看余额、Plan 和 Token 流水。

初始版本允许在第 5 至第 8 步直接操作 MySQL，并保留并发与一致性问题。

### 5.2 Token Plan 秒杀

1. 管理员创建秒杀活动和库存。
2. 活动开始前，用户进入活动页查看状态和剩余库存。
3. 活动开始后，用户发起抢购请求。
4. 初始版本直接查询和更新 MySQL 库存。
5. 用户获得订单后进入收银台。
6. 支付成功后生成用户 Token Plan。

秒杀核心代码由学习者实现：

- 先保留并复现 MySQL 超卖。
- 再实现 Redis 预扣库存和 Lua。
- 再通过 RabbitMQ 异步创建订单。
- 最后实现对账和异常补偿。

## 8. 订单状态机

```text
PENDING_PAYMENT
  ├─ 支付成功 -> PAID -> COMPLETED
  ├─ 用户取消 -> CANCELLED
  └─ 超时关闭 -> CLOSED
```

规则：

- 只有 `PENDING_PAYMENT` 可以支付。
- 只有 `PENDING_PAYMENT` 可以取消或超时关闭。
- `PAID` 和 `COMPLETED` 不允许重复支付。
- 关闭或取消时需要释放库存，重复释放必须幂等。

## 9. 初始版本与目标版本

| 能力 | 初始版本，由 AI 提供 | 目标版本，由学习者实现 |
| --- | --- | --- |
| 商品查询 | 每次查询 MySQL | Cache Aside + 缓存失效 |
| 普通下单 | 直接 SQL 扣库存 | 事务 + 锁或原子更新 |
| 支付后发 Token | 同事务或同步调用 | MQ 异步发放 + 幂等 |
| 订单超时 | 定时扫描数据库 | RabbitMQ 延迟队列 |
| 秒杀库存 | MySQL 查询后更新 | Redis Lua 预扣 + MQ 下单 |
| 消息可靠性 | 不实现 | 手动 ACK + 重试 + DLQ |
| 消费幂等 | 不实现 | 唯一消息 ID + 消费记录 |
| 缓存异常 | 不处理 | 穿透、击穿、雪崩方案 |

## 10. 非功能需求

### 10.1 性能

- 项目目标是学习和可复现，不以生产吞吐量为验收标准。
- 秒杀实验需要能够使用并发脚本复现超卖。
- 每个优化动作需要有前后对比数据。

### 10.2 安全

- 本地开发环境使用 JWT。
- 密码使用 BCrypt。
- Redis、MySQL 和 RabbitMQ 默认只监听本机。
- 不执行真实支付。
- 不把数据库密码、JWT 密钥提交到 Git。

### 10.3 可观测性

- 后端输出结构化或带追踪号的日志。
- 开启 MyBatis SQL 日志用于学习。
- 使用 RabbitMQ Management UI 观察消息。
- 使用 Redis CLI 或 Redis 桌面工具观察 Key。
- 提供复现实验脚本和预期结果。

### 10.4 兼容性

- Java 17。
- Spring Boot 3.x。
- Maven 3.9.x。
- MySQL 8.0.34。
- Redis 3.0.504 本机版本。
- RabbitMQ 4.3.6。
- Erlang/OTP 28.5。
- Node.js 24.x。
- React + TypeScript。

Redis 3.0.504 仅用于本地学习。教程不使用 Redis Streams、Redis Functions 和 Redis 7 专有功能。

## 11. 不在范围内

- 真实支付渠道。
- 退款、发票、物流和收货地址。
- 多商家和结算分账。
- 生产级高可用部署。
- 微服务、Kubernetes 和服务网格。
- 复杂推荐、搜索和风控。
- 完整优惠券体系。
- 多级管理员权限。

## 12. 验收标准

项目完成时，需要同时满足：

1. 用户端和管理端可以完整走通主要业务流程。
2. 初始 MySQL 版本能够复现库存超卖和订单一致性问题。
3. Redis 和 RabbitMQ 优化可以由学习者独立实现并解释。
4. 每个问题都有复现步骤、前后结果和结论。
5. 14 天课程全部具有可执行任务和验收标准。
6. Obsidian 图谱能够展示课程、概念、实验、问题、提交和文档之间的连接。
7. 开发日志可以按时间回顾每天完成的内容、证据和遗留问题。

## 13. 项目成功标准

项目成功不以界面复杂程度衡量，而以以下问题能否回答清楚衡量：

- 为什么缓存会不一致，什么时候删除缓存？
- 为什么加锁仍然可能超卖？
- 为什么消息会重复，消费方如何幂等？
- 为什么本地事务提交后消息可能没有发送成功？
- 为什么秒杀不能把流量直接打到 MySQL？
- 为什么 Redis 扣减成功后数据库订单仍然可能不存在？
- 如何发现并补偿 Redis、MQ 和 MySQL 之间的状态差异？
